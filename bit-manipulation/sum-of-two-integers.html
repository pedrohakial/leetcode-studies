371. Sum of Two Integers (Medium)

https://leetcode.com/problems/sum-of-two-integers/ · Tópico: Math · Bit Manipulation

Enunciado (resumo)

Dados dois inteiros a e b, devolver a soma deles sem usar os operadores + e -. Só bitwise (&, |, ^, <<, >>) e loops.

a = 1,  b = 2   → 3
a = 2,  b = 3   → 5
a = -2, b = 3   → 1
a = -1, b = -1  → -2

Padrão — o que decorar

Soma bit a bit com carry em loop:

  • a ^ b soma os bits SEM considerar o transporte (“soma sem carry”);
  • (a & b) << 1 calcula onde há transporte para a próxima casa (“carry”);
  • repete com a = xor, b = carry até o carry zerar.
  a=5  b=3     xor      &     carry
  101  011     110      001   010
  110  010     100      010   100
  100  100     000      100  1000
  000 1000    1000      000   0000 → 8 ✓

A pegadinha universal: a aritmética de 32 bits (ou n bits) roda circularmente — os inteiros são complemento de dois e o “teto” transborda de volta. Por isso:

  • Python não tem overflow natural: máscara & 0xFFFFFFFF a cada passo simula 32 bits, e o fim reconverte para signed;
  • C/C++ devem trabalhar em unsigned int (shift de signed negativo é UB e o bit de sinal participa da conta);
  • Rust pode usar u32 com cast final para i32 (WASM/CPU só veem os bits).

Pista no enunciado: somar sem + → pensar em half-adder (xor + carry) do curso de eletrônica digital.

Python

class Solution:
    def getSum(self, a: int, b: int) -> int:
        MASCARA = 0xFFFFFFFF          # Python não tem overflow: simula 32 bits
        while b:
            a, b = (a ^ b) & MASCARA, ((a & b) << 1) & MASCARA
        # reconverte o resultado de 32 bits unsigned para signed
        return a if a <= 0x7FFFFFFF else a - 0x100000000

Rust

#![allow(unused)]
fn main() {
impl Solution {
    pub fn get_sum(a: i32, b: i32) -> i32 {
        // u32 mantém a conta explícita em 32 bits; casts i32<->u32 são
        // reinterpretações (complemento de dois), não conversões de valor.
        let (mut a, mut b) = (a as u32, b as u32);
        while b != 0 {
            let carry = (a & b) << 1; // bits que precisam ir para a esquerda
            a ^= b;                  // soma sem carry
            b = carry;
        }
        a as i32
    }
}
}

C++

class Solution {
public:
    int getSum(int a, int b) {
        /* unsigned: shift de dado 'signed' com bit alto é UB em C++ */
        unsigned x = (unsigned)a, y = (unsigned)b;
        while (y) {
            unsigned carry = (x & y) << 1;
            x ^= y;
            y = carry;
        }
        return (int)x;
    }
};

C

int getSum(int a, int b) {
    unsigned x = (unsigned)a, y = (unsigned)b;
    while (y) {
        unsigned carry = (x & y) << 1; /* bits que precisam ir à esquerda */
        x ^= y;                        /* soma sem carry */
        y = carry;
    }

}

Complexidade

  • Tempo: O(1) — no pior caso, um carry anda por 32 casas; o loop executa no máximo 32 iterações (constante).
  • Espaço: O(1).

Pegadinhas

  • Máscara 0xFFFFFFFF no Python é OBRIGATÓRIA (a nota do enunciado): sem ela, a ^ b e o carry crescem bits infinitamente para a esquerda (os ints de Python são arbitrários) e o loop nunca zera o carry. A máscara em cada passo simula o wrap de 32 bits; o a - 0x100000000 no fim devolve o signed (bit 31 ligado = negativo).
  • C/C++: unsigned como regra — (x & y) << 1 com int de bit alto é comportamento indefinido (shift de negativo); com unsigned é sempre definido. O teste -1 + -1 é o que expõe isso.
  • Rust: shift de i32 é definido (não é UB como em C), mas trabalhar com u32 mantém o invariante de “32 bits” explícito — e (a & b) << 1 em i32 também funcionaria; o cast u32/i32 é reinterpretação, então 0xFFFFFFFF as i32 == -1. Nenhum wrapping_* é necessário com u32.
  • O << 1 do carry pode “extravasar” a 32ª casa — é exatamente o que deve acontecer (o transporte do bit 31 desaparece no wrap); nos unsigned ele é descartado e o loop termina.
  • Caso a == 0 ou b == 0: o loop nem roda (binário) — retorna o outro número; teste obrigatório (0 + 0 e 0 + x).
