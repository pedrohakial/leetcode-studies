973. K Closest Points to Origin (Medium)

https://leetcode.com/problems/k-closest-points-to-origin/ · Tópico: Heap (Priority Queue) · Geometry

Enunciado (resumo)

Dado um array de pontos [x, y] no plano e um k, devolver os k pontos mais próximos da origem (0,0). A distância é a euclidiana; comparar por distância² basta (evita sqrt e overflow). A ordem da resposta é livre.

points = [[1,3],[-2,2]], k = 1  →  [[-2,2]]
points = [[3,3],[5,-1],[-2,4]], k = 2  →  [[3,3],[-2,4]]

Padrão — o que decorar

Max-heap de tamanho k ordenado por distância: para manter os k MENORES, guarde num heap cuja raiz é o MAIOR entre eles — quando entra um ponto, se o heap passou de k, o pop remove o mais longe. O resultado é “os k menores com heap max” (o espelho de “os k maiores com heap min” do Top K). Pistas no enunciado: top k + distância → heap; ordenar tudo com sort também acerta o problema (O(n log n)) — o heap é a versão O(n log k) e a que sai no tópico.

Python

def kClosest(self, points: list[list[int]], k: int) -> list[list[int]]:
    heap = []
    for x, y in points:
        d = x * x + y * y
        heapq.heappush(heap, (-d, x, y))  # min-heap ordenado por -d²
        if len(heap) > k:
            heapq.heappop(heap)           # remove o MAIOR d²
    return [[x, y] for _, x, y in heap]

Rust

#![allow(unused)]
fn main() {
pub fn k_closest(points: Vec<Vec<i32>>, k: i32) -> Vec<Vec<i32>> {
    // heap max por distância²: quando estoura k, o pop remove o MAIS LONGE.
    // (i64 para a conta x²+y² nunca estourar i32: 10⁴² + 10⁴² cabe em i64.)
    let mut heap: BinaryHeap<(i64, i32, i32)> = BinaryHeap::new();
    for ponto in &points {
        let (x, y) = (ponto[0] as i64, ponto[1] as i64);
        heap.push((x * x + y * y, ponto[0], ponto[1]));
        if heap.len() > k as usize {
            heap.pop();
        }
    }
    heap.into_iter().map(|(_, x, y)| vec![x, y]).collect()
}
}

C++

vector<vector<int>> kClosest(vector<vector<int>>& points, int k) {
    // max-heap de (dist², x, y): estourou k, pop remove o MAIS LONGE.
    // distância em long long: x²+y² com |x|,|y| <= 10^4 cabe em int,
    // mas a boa prática é não confiar nisso.
    priority_queue<pair<long long, pair<int, int>>> heap;
    for (auto& p : points) {
        long long d = 1LL * p[0] * p[0] + 1LL * p[1] * p[1];
        heap.push({d, {p[0], p[1]}});
        if ((int)heap.size() > k) heap.pop();
    }
    vector<vector<int>> resp;
    while (!heap.empty()) {
        auto [d, xy] = heap.top(); // structured binding (C++17)
        resp.push_back({xy.first, xy.second});
        heap.pop();
    }
    return resp;
}

C

typedef struct { long long dist; int x; int y; } Ponto;
typedef struct { Ponto* arr; int tamanho; } HeapMax;

/**
 * Return an array of arrays of size *returnSize.
 * The sizes of the arrays are returned as *returnColumnSizes array.
 */
int** kClosest(int** points, int pointsSize, int* pointsColSize, int k,
               int* returnSize, int** returnColumnSizes) {
    (void)pointsColSize; /* sempre 2 no problema; assinatura do LeetCode */
    /* push-then-pop: o heap cabe k+1 elementos transitoriamente */
    HeapMax h = {malloc((size_t)(k + 1) * sizeof(Ponto)), 0};
    for (int i = 0; i < pointsSize; i++) {
        long long d = (long long)points[i][0] * points[i][0]
                    + (long long)points[i][1] * points[i][1];
        Ponto p = {d, points[i][0], points[i][1]};
        push(&h, p);
        if (h.tamanho > k) pop(&h); /* remove o mais longe */
    }
    int** resp = (int**)malloc((size_t)k * sizeof(int*));
    *returnColumnSizes = (int*)malloc((size_t)k * sizeof(int));
    *returnSize = k;
    for (int i = 0; i < k; i++) {
        resp[i] = (int*)malloc(2 * sizeof(int));
        (*returnColumnSizes)[i] = 2;
        resp[i][0] = h.arr[i].x; /* heap max: arr[i] são os k mais próximos */
        resp[i][1] = h.arr[i].y;
    }
    free(h.arr);
    return resp;
}

Complexidade

  • Tempo: O(n log k) — n pontos, cada push/pop em heap ≤ k é O(log k). (O sort ingênuo dá O(n log n); o quickselect dá O(n) médio — outro caminho válido no tópico “Divide and Conquer”.)
  • Espaço: O(k) — o heap guarda no máximo k pontos (+ o C aloca a resposta de k linhas, que é o retorno pedido).

Pegadinhas

  • Comparar por distância² — nenhum sqrt, e a ordem relativa é idêntica.
  • Overflow da distância: limite do problema (±10⁴)² + (±10⁴)² = 2·10⁸ ainda cabe em int, mas em Rust/C é tráfego de convenção usar i64/long long (em Python não há overflow, mas dê o hábito).
  • A ordem da resposta é livre — não perca tempo ordenando a saída no heap; o juiz aceita qualquer ordem dos k mais próximos.
  • “k menores → max-heap”: a inversão mental é a fonte nº 1 de erro (se você usar min-heap de tamanho k, o topo é o menor e o pop joga fora o ponto que deveria ficar).
  • Em C: o heap cabe k+1 transitoriamente (push seguido de pop) — o malloc de k exato é heap overflow silencioso; o retorno usa o protocolo returnSize/returnColumnSizes da assinatura do LeetCode.
