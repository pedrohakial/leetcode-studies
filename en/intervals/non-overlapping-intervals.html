435. Non-overlapping Intervals (Medium)

https://leetcode.com/problems/non-overlapping-intervals/ · Topic: Intervals

Problem (summary)

Given a list of intervals, return the minimum number of intervals to remove so that the rest don’t overlap. Two intervals that merely touch ([1,2] and [2,3]) are not an overlap.

intervals = [[1,2],[2,3],[3,4],[1,3]]     →  1              (remove [1,3])
intervals = [[1,2],[1,2],[1,2]]           →  2

Pattern — what to memorize

Greedy by “earliest end” (interval scheduling): sort by end and count how many intervals can stay — keep the current one if it starts after the previously kept one ended (start >= prev_end); the answer is simply “minimum to remove = total − kept”. Why sort by end and not by start? Whoever ends earlier frees up space faster, leaving maximum room for the rest — the same principle as “pick the meeting that ends first” from classic scheduling.

Python

class Solution:
    def eraseOverlapIntervals(self, intervals: list[list[int]]) -> int:
        # greedy by earliest end: keep whoever ends first
        intervals.sort(key=lambda x: x[1])
        fim_anterior = float("-inf")
        mantidos = 0
        for inicio, fim in intervals:
            if inicio >= fim_anterior:   # doesn't touch the previously kept one
                mantidos += 1
                fim_anterior = fim
        return len(intervals) - mantidos

The answer is what’s left outside: solving “maximum number of intervals that fit” is easier than choosing what to remove.

Rust

#![allow(unused)]
fn main() {
impl Solution {
    pub fn erase_overlap_intervals(intervals: Vec<Vec<i32>>) -> i32 {
        let mut intervalos = intervals;
        // greedy by earliest end: keep whoever ends first
        intervalos.sort_by_key(|i| i[1]);
        let mut fim_anterior = i32::MIN;
        let mut mantidos = 0i32;
        for intervalo in &intervalos {
            if intervalo[0] >= fim_anterior {
                mantidos += 1;
                fim_anterior = intervalo[1];
            }
        }
        intervalos.len() as i32 - mantidos
    }
}
}

C++

#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
public:
    int eraseOverlapIntervals(vector<vector<int>>& intervals) {
        // greedy by earliest end: keep whoever ends first
        sort(intervals.begin(), intervals.end(),
             [](const vector<int>& a, const vector<int>& b) { return a[1] < b[1]; });
        int fimAnterior = INT_MIN, mantidos = 0;
        for (auto& iv : intervals) {
            if (iv[0] >= fimAnterior) { // doesn't touch the previously kept one
                mantidos++;
                fimAnterior = iv[1];
            }
        }
        return (int)intervals.size() - mantidos;
    }
};

C

#include <stdlib.h>

static int cmp_por_fim(const void* a, const void* b) {
    const int* x = *(const int* const*)a;
    const int* y = *(const int* const*)b;
    return (x[1] > y[1]) - (x[1] < y[1]); /* NEVER "x - y" (overflow) */
}

int eraseOverlapIntervals(int** intervals, int intervalsSize, int* intervalsColSize) {
    (void)intervalsColSize;
    if (intervalsSize == 0) return 0;
    /* greedy by earliest end: keep whoever ends first */
    qsort(intervals, intervalsSize, sizeof(int*), cmp_por_fim);
    int fim_anterior = intervals[0][1];
    int mantidos = 1;
    for (int i = 1; i < intervalsSize; i++) {
        if (intervals[i][0] >= fim_anterior) { /* doesn't touch the kept one */
            mantidos++;
            fim_anterior = intervals[i][1];
        }
    }
    return intervalsSize - mantidos;
}

Complexity

  • Time: O(n log n) — the sort dominates; the sweep is O(n).
  • Space: O(1) beyond the sort (C: O(log n) of qsort stack).

Pitfalls

  • Sort by end, not by start — sorting by start breaks the greedy (the longest interval would win the spot it doesn’t deserve).
  • Touching is not overlapping: keeping requires start >= prev_end, not >.
  • Contained ([1,4] and [2,3]): the one with the larger end is dropped naturally — the smaller-end one ([2,3]) comes first under sort-by-end and [1,4] doesn’t touch the kept one, so it’s discarded.
  • All identical ([[1,2]]×3): keep 1, remove 2.
  • C/C++: i32::MIN/INT_MIN as sentinel works because the constraints are ≥ −10⁴ — point that out if the interviewer asks about the magic value.
  • Rust: sort_by_key on a Copy field; if the struct field weren’t Copy, sort_by would be needed to avoid moving.
