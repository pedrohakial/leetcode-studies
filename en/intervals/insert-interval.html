57. Insert Interval (Medium)

https://leetcode.com/problems/insert-interval/ · Topic: Intervals

Problem (summary)

Given a list of intervals already sorted by start with no overlaps between them, and a new interval, insert it in the correct position, merging with everything it touches. Return the resulting list.

intervals = [[1,3],[6,9]], newInterval = [2,5]            →  [[1,5],[6,9]]
intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]], [4,8]     →  [[1,2],[3,10],[12,16]]

Pattern — what to memorize

Linear sweep in 3 phases — (1) copy the intervals that end before the new one starts; (2) merge the ones that touch the new interval (condition start <= end), stretching the new one on every touch; (3) copy what comes after. Because the input is already sorted, a single pass does it — the tell is “ordered” + “insert”: no re-sorting, no two pointers.

Python

class Solution:
    def insert(self, intervals: list[list[int]], newInterval: list[int]) -> list[list[int]]:
        inicio, fim = newInterval
        antes, depois = [], []
        for intervalo in intervals:
            if intervalo[1] < inicio:        # ends before the new one starts
                antes.append(intervalo)
            elif intervalo[0] > fim:         # starts after the new one ends
                depois.append(intervalo)
            else:                            # touches/overlaps: stretch the new one
                inicio = min(inicio, intervalo[0])
                fim = max(fim, intervalo[1])
        return antes + [[inicio, fim]] + depois

No indices, no while — the elif already splits the 3 phases. This is the interview version: 8 lines, impossible to trip an off-by-one.

Rust

#![allow(unused)]
fn main() {
impl Solution {
    pub fn insert(intervals: Vec<Vec<i32>>, new_interval: Vec<i32>) -> Vec<Vec<i32>> {
        let (mut inicio, mut fim) = (new_interval[0], new_interval[1]);
        let mut resp: Vec<Vec<i32>> = Vec::new();
        let mut i = 0;
        // intervals that end before the new one starts: copy straight across
        while i < intervals.len() && intervals[i][1] < inicio {
            resp.push(intervals[i].clone());
            i += 1;
        }
        // merge everything that touches the new interval (boundaries included)
        while i < intervals.len() && intervals[i][0] <= fim {
            inicio = inicio.min(intervals[i][0]);
            fim = fim.max(intervals[i][1]);
            i += 1;
        }
        resp.push(vec![inicio, fim]);
        // and what comes after
        while i < intervals.len() {
            resp.push(intervals[i].clone());
            i += 1;
        }
        resp
    }
}
}

Cloning the intervals that pass through untouched is the honest way to not fight the borrow checker (the problem hands you the Vec by value anyway).

C++

#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<vector<int>> insert(vector<vector<int>>& intervals, vector<int>& newInterval) {
        vector<vector<int>> resp;
        int inicio = newInterval[0], fim = newInterval[1];
        int i = 0, n = (int)intervals.size();
        // intervals that end before the new one starts: copy straight across
        while (i < n && intervals[i][1] < inicio)
            resp.push_back(intervals[i++]);
        // merge everything that touches the new interval (boundaries included)
        while (i < n && intervals[i][0] <= fim) {
            inicio = min(inicio, intervals[i][0]);
            fim = max(fim, intervals[i][1]);
            i++;
        }
        resp.push_back({inicio, fim});
        // and what comes after
        while (i < n)
            resp.push_back(intervals[i++]);
        return resp;
    }
};

C

#include <stdlib.h>

int** insert(int** intervals, int intervalsSize, int* intervalsColSize,
             int* newInterval, int newIntervalSize, int* returnSize,
             int** returnColumnSizes) {
    (void)intervalsColSize;
    (void)newIntervalSize;
    int** resp = malloc((intervalsSize + 1) * sizeof(int*));
    *returnColumnSizes = malloc((intervalsSize + 1) * sizeof(int));
    int n = 0, i = 0;
    int inicio = newInterval[0], fim = newInterval[1];
    /* before: ends before the new one starts */
    while (i < intervalsSize && intervals[i][1] < inicio) {
        resp[n] = malloc(2 * sizeof(int));
        resp[n][0] = intervals[i][0];
        resp[n][1] = intervals[i][1];
        (*returnColumnSizes)[n] = 2;
        n++; i++;
    }
    /* merge everything that touches the new interval */
    while (i < intervalsSize && intervals[i][0] <= fim) {
        if (intervals[i][0] < inicio) inicio = intervals[i][0];
        if (intervals[i][1] > fim) fim = intervals[i][1];
        i++;
    }
    resp[n] = malloc(2 * sizeof(int));
    resp[n][0] = inicio;
    resp[n][1] = fim;
    (*returnColumnSizes)[n] = 2;
    n++;
    /* after */
    while (i < intervalsSize) {
        resp[n] = malloc(2 * sizeof(int));
        resp[n][0] = intervals[i][0];
        resp[n][1] = intervals[i][1];
        (*returnColumnSizes)[n] = 2;
        n++; i++;
    }
    *returnSize = n;
    return resp;
}

Complexity

  • Time: O(n) — one single pass; no sorting (the input is already sorted).
  • Space: O(n) — the answer holds at most n + 1 intervals.

Pitfalls

  • “Touching” counts as overlap: [1,2] plus a new [2,3] merges into [1,3]. The merge condition is intervals[i][0] <= fim, not < — the <= vs < mistake is the most common one in this problem.
  • New interval that touches nothing: it lands at the front (empty first phase) or at the back (empty third phase) — the 3-phase code covers both alone.
  • New interval that swallows several at once: phase 2 stretches inicio/fim cumulatively.
  • Empty input: return just the new interval.
  • C: the answer can hold n + 1 intervals — allocate (n + 1), not n. returnColumnSizes must be allocated with the same size.
  • C++: the signature takes vector<int>& — in the interview, always pass a named variable, never a loose {...} as an argument.
