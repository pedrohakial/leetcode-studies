4. Median of Two Sorted Arrays (Hard)

https://leetcode.com/problems/median-of-two-sorted-arrays/ · Topic: Array · Binary Search · Divide and Conquer

Problem (summary)

Given two sorted arrays nums1 and nums2 (sizes m and n), return the median of their union, in O(log(m+n)) time. The median is the middle element if the total is odd, or the average of the two central ones if even.

nums1 = [1,3], nums2 = [2]    → 2.0
nums1 = [1,2], nums2 = [3,4]  → 2.5
nums1 = [],    nums2 = [1]    → 1.0

Pattern — what to memorize

Binary partitioning on the SMALLER array (the cut technique). The median splits the union into two halves of sizes (m+n+1)/2 (left) and the rest (right). The idea: pick corte_a (how much of the left half comes from A) and corte_b = metade - corte_a (how much comes from B) such that:

  • esq_a <= dir_b and esq_b <= dir_a → the partition is correct: the median is max(esq_a, esq_b) (odd) or the average with min(dir_a, dir_b) (even);
  • esq_a > dir_b → A’s left side is “too big” → cut less in A;
  • otherwise → cut more in A.

The only way to guarantee the cut satisfies the condition is binary search on the smaller array (O(log min(m,n))) — searching both is O(log(m+n)) in practice, but the min is the tight bound and avoids a search on the larger array being O(log m + log n).

Clue in the statement: two sorted + median + O(log) → a pair of cuts with the “entire left ≤ entire right” invariant. What makes it Hard: the edge cases at the ends (± infinity) and the cut bookkeeping.

Python

class Solution:
    def findMedianSortedArrays(self, nums1: list[int], nums2: list[int]) -> float:
        a, b = nums1, nums2
        if len(a) > len(b):
            a, b = b, a          # search the smaller one; the other is the complement
        m, n = len(a), len(b)
        lo, hi = 0, m
        metade = (m + n + 1) // 2
        INF = float("inf")
        while lo <= hi:
            corte_a = (lo + hi) // 2
            corte_b = metade - corte_a
            esq_a = a[corte_a - 1] if corte_a > 0 else -INF
            esq_b = b[corte_b - 1] if corte_b > 0 else -INF
            dir_a = a[corte_a] if corte_a < m else INF
            dir_b = b[corte_b] if corte_b < n else INF
            if esq_a <= dir_b and esq_b <= dir_a:   # correct partition
                if (m + n) % 2 == 1:
                    return max(esq_a, esq_b)
                return (max(esq_a, esq_b) + min(dir_a, dir_b)) / 2.0
            if esq_a > dir_b:
                hi = corte_a - 1   # a's left side is "too big"
            else:
                lo = corte_a + 1
        return 0.0  # unreachable

Rust

#![allow(unused)]
fn main() {
impl Solution {
    pub fn find_median_sorted_arrays(nums1: Vec<i32>, nums2: Vec<i32>) -> f64 {
        // Independent references: a = smaller array, b = larger (no copy).
        let (a, b) = if nums1.len() > nums2.len() {
            (&nums2, &nums1)
        } else {
            (&nums1, &nums2)
        };
        let (m, n) = (a.len(), b.len());
        let metade = (m + n + 1) / 2; // elements in the left partition
        let (mut lo, mut hi) = (0usize, m); // hi INCLUSIVE here (cut can be m)
        while lo <= hi {
            let corte_a = lo + (hi - lo) / 2;
            let corte_b = metade - corte_a;
            let esq_a = if corte_a > 0 { a[corte_a - 1] } else { i32::MIN };
            let esq_b = if corte_b > 0 { b[corte_b - 1] } else { i32::MIN };
            let dir_a = if corte_a < m { a[corte_a] } else { i32::MAX };
            let dir_b = if corte_b < n { b[corte_b] } else { i32::MAX };
            if esq_a <= dir_b && esq_b <= dir_a {
                let max_esq = esq_a.max(esq_b);
                if (m + n) % 2 == 1 {
                    return max_esq as f64;
                }
                return (max_esq + dir_a.min(dir_b)) as f64 / 2.0;
            }
            if esq_a > dir_b {
                hi = corte_a - 1; // a's left side too big
            } else {
                lo = corte_a + 1;
            }
        }
        0.0 // unreachable with valid inputs
    }
}
}

C++

class Solution {
public:
    double findMedianSortedArrays(vector<int>& a, vector<int>& b) {
        /* You can't "re-point" references: the swap is a call with the
         * arguments flipped (without mutating the caller's vectors). */
        if (a.size() > b.size()) return findMedianSortedArrays(b, a);
        int m = (int)a.size(), n = (int)b.size();
        const int NEG_INF = INT_MIN, POS_INF = INT_MAX;
        int lo = 0, hi = m;
        int metade = (m + n + 1) / 2; /* elements in the left partition */
        while (lo <= hi) {
            int corte_a = lo + (hi - lo) / 2;
            int corte_b = metade - corte_a;
            int esq_a = corte_a > 0 ? a[corte_a - 1] : NEG_INF;
            int esq_b = corte_b > 0 ? b[corte_b - 1] : NEG_INF;
            int dir_a = corte_a < m ? a[corte_a] : POS_INF;
            int dir_b = corte_b < n ? b[corte_b] : POS_INF;
            if (esq_a <= dir_b && esq_b <= dir_a) { /* correct partition */
                int max_esq = max(esq_a, esq_b);
                if ((m + n) % 2 == 1) return max_esq;
                return (max_esq + min(dir_a, dir_b)) / 2.0;
            }
            if (esq_a > dir_b) hi = corte_a - 1; /* a's left side too big */
            else lo = corte_a + 1;
        }
        return 0.0; /* unreachable */
    }
};

C

#include <stdint.h>

#define NEG_INF (-2147483647 - 1) /* INT_MIN without overflowing the literal */
#define POS_INF 2147483647

double findMedianSortedArrays(int* nums1, int nums1Size,
                              int* nums2, int nums2Size) {
    int* a = nums1; int m = nums1Size;
    int* b = nums2; int n = nums2Size;
    if (m > n) { int* t = a; a = b; b = t; int s = m; m = n; n = s; }

    int lo = 0, hi = m;
    int metade = (m + n + 1) / 2;
    while (lo <= hi) {
        int corte_a = lo + (hi - lo) / 2;
        int corte_b = metade - corte_a;
        int esq_a = corte_a > 0 ? a[corte_a - 1] : NEG_INF;
        int esq_b = corte_b > 0 ? b[corte_b - 1] : NEG_INF;
        int dir_a = corte_a < m ? a[corte_a]     : POS_INF;
        int dir_b = corte_b < n ? b[corte_b]     : POS_INF;
        if (esq_a <= dir_b && esq_b <= dir_a) {
            int max_esq = esq_a > esq_b ? esq_a : esq_b;
            if ((m + n) % 2 == 1) return (double)max_esq;
            int min_dir = dir_a < dir_b ? dir_a : dir_b;
            return (max_esq + min_dir) / 2.0;
        }
        if (esq_a > dir_b) hi = corte_a - 1; /* a's left side too big */
        else lo = corte_a + 1;
    }
    return 0.0; /* unreachable with valid inputs */
}

Complexity

  • Time: O(log(min(m, n))) — the binary search only walks the smaller array; the other is the cut’s complement (an O(1)-per-iteration step).
  • Space: O(1) — indices only (Python/Rust/C++ don’t copy the arrays; in C, pointer swap).

Pitfalls

  • Sentinel at the ends: when the cut hits a boundary (corte_a == 0), esq_a doesn’t exist — using -INF/INT_MIN/i32::MIN keeps the “left ≤ right” condition true. Forgetting this is mistake #1.
  • metade = (m+n+1)/2 counts the left partition; the +1 makes the cut consistent for odd totals (median on the left) and even (two central values split between the halves).
  • Even average: (max_esq + min_dir) / 2.0 — division by 2.0 (f64), not integer // 2 (which would truncate).
  • Overflow of l+r and a + b: m*n fits in 32 bits, but l + r near INT_MAX can overflow — lo + (hi - lo) / 2 avoids it (as always).
  • C++ swap(a, b) mutates the caller: with references, swapping the contents changes the original vectors and breaks the test sequence; the recursive call with flipped arguments is the idiom (and m = n in C swaps the pointers).
  • Case [] and a single element: [],[1] → sentinels on both sides; corte_b must stay within [0, n] — the m <= n guarantee is what keeps corte_b in range.
