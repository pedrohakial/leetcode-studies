74. Search a 2D Matrix (Medium)

https://leetcode.com/problems/search-a-2d-matrix/ · Tópico: Array · Binary Search · Matrix

Enunciado (resumo)

Uma matriz m × n onde cada linha é ordenada crescente e o primeiro elemento de cada linha é maior que o último da linha anterior (no fundo, um vetor ordenado “achatado”). Dado target, devolver se ele existe na matriz.

matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]], target = 3  → true
matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]], target = 13 → false

Padrão — o que decorar

Busca binária linearizada: o invariante da matriz (linhas e colunas ordenadas, com o 1º de cada linha maior que o último da anterior) garante que a leitura em ordem é um vetor crescente de m*n elementos. Então finge-se que é um vetor: índices 0..m*n, e o elemento da posição k é matrix[k / n][k % n]. Uma única busca binária O(log(m·n)) — sem achar a linha primeiro.

Pista no enunciado: matriz ordenada em linhas e colunas encadeadas → tratar como 1D. A pegadinha inversa: se as linhas fossem só ordenadas entre si (não encadeadas), aí sim seriam duas buscas binárias (coluna 0 e depois a linha).

Python

class Solution:
    def searchMatrix(self, matrix: list[list[int]], target: int) -> bool:
        m, n = len(matrix), len(matrix[0])
        l, r = 0, m * n - 1
        while l <= r:
            mid = (l + r) // 2
            v = matrix[mid // n][mid % n]
            if v == target:
                return True
            if v < target:
                l = mid + 1
            else:
                r = mid - 1
        return False

Rust

#![allow(unused)]
fn main() {
impl Solution {
    pub fn search_matrix(matrix: Vec<Vec<i32>>, target: i32) -> bool {
        let m = matrix.len();
        let n = matrix[0].len();
        // Busca com limite superior EXCLUSIVO [l, r): `r = mid` nunca precisa
        // de `mid - 1`, então usize não underflowa quando mid = 0.
        let (mut l, mut r) = (0usize, m * n);
        while l < r {
            let mid = l + (r - l) / 2;
            let v = matrix[mid / n][mid % n];
            if v == target {
                return true;
            }
            if v < target {
                l = mid + 1;
            } else {
                r = mid;
            }
        }
        false
    }
}
}

C++

class Solution {
public:
    bool searchMatrix(vector<vector<int>>& matrix, int target) {
        int m = (int)matrix.size(), n = (int)matrix[0].size();
        int l = 0, r = m * n - 1;
        while (l <= r) {
            int mid = l + (r - l) / 2;
            int v = matrix[mid / n][mid % n];
            if (v == target) return true;
            if (v < target) l = mid + 1;
            else r = mid - 1;
        }
        return false;
    }
};

C

#include <stdbool.h>

bool searchMatrix(int** matrix, int matrixSize, int* matrixColSize, int target) {
    int n = matrixColSize[0];
    int l = 0, r = matrixSize * n - 1;
    while (l <= r) {
        int m = l + (r - l) / 2;
        int v = matrix[m / n][m % n];
        if (v == target) return true;
        if (v < target) l = m + 1;
        else r = m - 1;
    }
    return false;
}

Complexidade

  • Tempo: O(log(m·n)) — a busca binária opera sobre m*n posições “virtuais”; cada acesso à matriz é O(1).
  • Espaço: O(1) — só índices.

Pegadinhas

  • Matriz vazia: os limites do enunciado garantem m, n >= 1, mas se o código rodar com matriz vazia, matrix[0]/matrix[0].size() já quebra antes da busca — trate m == 0 antes se for defensivo (entrevista de sênior fala disso de boca).
  • r = m * n - 1 em usize: se m*n == 0 (matriz vazia), underflowa. Por isso a versão Rust usa o intervalo exclusivo [l, r) — nunca faz mid - 1, e a versão em C/C++ depende do m*n >= 1 garantido.
  • Elementos consecutivos entre linhas: é o matrix[1][0] > matrix[0][n-1] que torna a linearização válida; sem isso, o algoritmo quebra (e o teste target = 60 — o último elemento — cobre a fronteira da última linha).
  • mid % n e mid / n com n vindo de matrixColSize[0] no C: é a largura, não o número de linhas — inverter isso indexa ilegal.
